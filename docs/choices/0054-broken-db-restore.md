# DB가 깨졌을 때 로그인 없이 복원 (#54)

정전이나 디스크 문제로 데이터 파일(DB)이 깨지면 앱이 켜지지 않는다. 직원 PIN도 그 파일 안에 있어서 로그인도 못 한다. 앱을 켠 사람이 그 자리에서 백업으로 되돌릴 수 있게 했다.

- 관련: ADR 0011(백업), 업무 규칙의 역할별 표(백업 관리의 복원 예외), BR-K13(접속 기록). 화면은 "데이터 파일이 손상되었습니다"(복원 화면), 직원 관리의 백업 탭
- 사용자 흐름
  1. 호스트 PC에서 앱을 켜면 로그인 대신 "데이터 파일이 손상되었습니다" 화면이 뜬다.
  2. "가장 최근 정상 백업으로 되돌릴까요?" 아래에 백업 시각과 종류, 학기, 회원 수, 신청 수가 보인다.
  3. [되돌리기]를 누르면 앱이 다시 켜지고 평소처럼 로그인한다.
  4. 다른 백업을 쓰려면 "다른 백업 고르기" 목록이나 [다른 곳의 백업 파일 고르기](USB, 두 번째 위치)를 쓴다.
- 알아둘 점
  - 호스트 PC의 창에서만 된다. 다른 PC는 호스트에 닿지 못한다는 오류만 본다.
  - 회원 이름 같은 데이터는 보여 주지 않는다.
  - 깨진 파일은 데이터 폴더에 하나만 남는다(`baeum-maru.broken.db`).
  - 깨진 파일에서 일부 살리기, 빈 데이터로 새로 시작하기는 없다.
  - 누가 복원했는지는 남지 않는다. 접속 기록에는 직원 칸이 빈 "복원"이 남는다.
- 웹페이지 안내: 백업·복원 안내 - DB가 깨졌을 때 로그인 없이 복원하는 화면 추가

## 깨졌는지 어떻게 알아챌까

- 후보
  - 파일이 열리지 않을 때만
  - 열리지 않을 때 + 켤 때마다 빠른 검사(SQLite `quick_check`)
  - 열리지 않을 때 + 켤 때마다 전체 검사(`integrity_check`)
- 고른 것: 열리지 않을 때 + 빠른 검사
- 이유
  - 파일 앞부분이 멀쩡하면 열리기는 한다. 뒤쪽이 깨진 것은 쓰다가 갑자기 오류가 난다. 열기만 보면 놓친다. (테스트로 확인: 뒤쪽을 덮어쓴 DB가 열리고 빠른 검사에서 걸림)
  - 전체 검사는 데이터가 쌓일수록 켜는 시간이 길어진다. 빠른 검사는 색인 내용 대조를 건너뛰어 훨씬 빠르고, 파일 구조가 깨진 것은 잡는다. (원리만: 켜는 시간은 재지 않음)

## 로그인 없이 되돌리는 길을 어디에 낼까

- 후보
  - 호스트 서버에 로그인 없는 복원 주소
  - 앱 명령(그 PC의 창 안에서만 부를 수 있음)
- 고른 것: 앱 명령
- 이유
  - 서버 주소는 같은 네트워크의 다른 PC에서도 닿는다. 로그인 없는 주소가 하나라도 있으면 누구나 데이터를 되돌릴 수 있다.
  - 앱 명령은 호스트 PC 앞에 앉은 사람만 쓸 수 있다. 게다가 켤 때 "깨짐"으로 판정한 경우에만 동작한다.

## 어느 백업을 권할까

- 후보
  - 가장 최근 백업
  - 가장 최근의 정상 백업(새것부터 하나씩 살펴봄)
  - 권하지 않고 목록에서 고르게
- 고른 것: 가장 최근의 정상 백업을 권하고, 목록이나 다른 곳(USB, 두 번째 위치)의 파일도 고를 수 있게
- 이유
  - 디스크가 고장 나면 최근 백업도 같이 상했을 수 있다. 상한 백업을 권하면 두 번 실패한다. (테스트로 확인: 깨진 백업은 건너뛰고 그다음 것을 권함)
  - 당황한 상황이라 고를 것이 많으면 어렵다. 권하는 하나를 맨 앞에 두고 버튼 하나로 끝나게 했다.

## 깨진 파일을 어떻게 할까

- 후보
  - 지운다
  - 매번 날짜를 붙여 남긴다
  - 하나만 남기고 다음에 또 깨지면 덮어쓴다
- 고른 것: 하나만 남긴다
- 이유
  - 깨진 파일에서도 일부를 살릴 수 있을지 모르니 바로 지우지 않는다.
  - 깨진 파일도 회원 정보 사본이다. 여러 개 쌓이면 관리되지 않는 개인정보가 늘어난다.

## 깨진 게 아니라 더 새 버전 앱의 DB라면

- 후보
  - 깨진 것과 똑같이 복원 화면
  - 업데이트하라는 안내만
- 고른 것: 안내만. 화면에는 "앱을 새 버전으로 바꿔 주세요"가 뜬다.
- 이유: 파일은 멀쩡하다. 새 버전 앱을 쓰다가 옛 버전으로 켠 경우다. 복원하면 백업 이후의 데이터를 잃는다.

## 쓸 수 있는 백업이 하나도 없다면

- 후보
  - "빈 데이터로 새로 시작" 버튼
  - 다른 곳의 백업 파일을 고르라는 안내만
- 고른 것: 안내만
- 이유: 빈 데이터로 시작하는 버튼은 실수로 누르면 되돌릴 수 없다. 정말 필요하면 따로 정한다.

## 파일을 언제 바꿔 넣을까

- 후보
  - 평소 복원처럼 받아 두고 앱을 다시 켜며 바꾼다
  - 그 자리에서 바로 바꾼다
- 고른 것: 그 자리에서 바꾼다
- 이유: 평소에는 서버가 DB를 쥐고 있어 다시 켜야 한다. 깨졌을 때는 서버를 띄우지 않아 DB를 쥔 곳이 없다. 바꾼 뒤 한 번만 다시 켠다. (직접 확인: `just break-db` 뒤 개발 모드에서 되돌리고 다시 켜짐)

## 누가 복원했는지

- 후보
  - 복원 화면에서 이름이나 PIN을 받는다
  - 접속 기록에 복원을 남기고 직원 칸은 비운다
- 고른 것: 직원 칸을 비운다
- 이유: PIN을 확인할 DB가 깨져 있다. 확인할 수 없는 이름을 받아 적으면 기록이 틀릴 수 있다.
