# 호스트 PC를 다른 PC로 넘기기 (#82)

호스트 PC를 바꿀 때 데이터를 넘기기 파일로 옮기게 했다. 넘긴 옛 호스트는 접수를 받지 않고, 다른 PC들은 옛 호스트에 다시 붙지 않는다.

- 관련: ADR 0002(구현 메모), 0004, 0011, 0021. BR-H1~H5, BR-K13·K17, 역할별 표의 "호스트 넘기기·넘기기 취소", "넘겨받기". 화면은 백업 탭의 [호스트 넘기기], "호스트 넘기기" 화면, "이 PC는 호스트를 넘겼습니다" 화면, 처음 고르기 화면의 "넘겨받은 파일로 호스트 시작"
- 사용자 흐름
  1. 관리자가 옛 호스트 PC에서 직원 관리 > 백업 탭의 [호스트 넘기기]를 누르고 PIN을 넣는다. 앱이 다시 켜진다.
  2. "호스트 넘기기" 화면에서 학기와 회원·신청 수를 확인하고 [넘기기 파일 저장]을 누른다. 저장 창에서 USB 같은 곳을 고른다.
  3. 옛 호스트 PC는 "이 PC는 호스트를 넘겼습니다" 화면이 된다.
  4. 새 PC에서 배움마루를 처음 켜고 "넘겨받은 파일로 호스트 시작"을 고른다. 접속 모드로 쓰던 PC라면 주소·승인 화면의 [넘겨받은 파일로 호스트 시작]을 누른다.
  5. 넘기기 파일을 고르고, 그 파일 안의 관리자를 골라 PIN을 넣고 [이 파일로 호스트 시작]을 누른다.
  6. 다른 PC들은 [주소 다시 입력]으로 새 호스트 주소만 넣는다. 다시 승인받지 않고 로그인 화면으로 간다.
- 알아둘 점
  - 넘기는 동안(1~2 사이) 다른 PC는 배움마루를 쓸 수 없다.
  - 옛 호스트 PC의 데이터와, 새 PC에 남아 있던 예전 데이터는 지우지 않는다. 새 PC의 예전 데이터는 "넘겨받기 직전" 백업으로 남는다.
  - 옛 호스트 PC가 고장 났을 때 백업으로 새 호스트를 시작하는 일은 이번에 따로 만들지 않았다. 다음 이슈에서 다룬다.
  - 앱끼리 네트워크로 넘기기, 다른 PC에 새 주소 알려 주기는 하지 않는다.
  - 넘겨받는 PC에서 틀린 PIN은 잠금 횟수(BR-K7)에 들어가지 않는다.
- 웹페이지 안내: 설치·데이터 위치 안내에 "호스트 PC를 바꿀 때: 옛 PC의 백업 탭에서 [호스트 넘기기]로 파일을 저장하고, 새 PC에서 [넘겨받은 파일로 호스트 시작]" 한 줄을 더한다.

## 무엇으로 넘기나

- 후보
  - 백업과 같은 DB 파일 하나
  - 앱끼리 네트워크로 바로 보내기
- 고른 것: 백업과 같은 DB 파일
- 이유: 백업 복원의 파일 검사(깨진 파일, 더 새 버전)를 그대로 쓴다. 네트워크가 막힌 기관에서도 USB로 옮길 수 있다. 네트워크로 보내기는 ADR 0002에서 "필요해지면 나중에"로 미뤘다.

## 넘기는 동안 다른 PC를 막나

- 후보
  - 서버를 켠 채 파일을 만든다
  - 서버를 끄고 DB만 열어 파일을 만든다
- 고른 것: 서버를 끄고 만든다
- 이유: 파일을 만드는 사이 다른 PC가 신청을 저장하면, 그 신청은 새 호스트로 가지 않고 옛 호스트에만 남는다. 앱을 "넘기는 중"으로 다시 켜서 서버 없이 만든다. (원리만)

## 넘긴 옛 호스트는 어떻게 되나

- 후보
  - 그대로 호스트로 둔다(경고만)
  - 멈추고 넘김 화면만 보여 준다
- 고른 것: 멈춘다
- 이유: 옛 호스트가 계속 켜져 있으면 직원이 모르고 옛 호스트에 접수해 명단이 둘로 갈라진다(ADR 0002 "호스트는 하나"). 데이터는 지우지 않아 필요하면 되돌릴 수 있다.

## 파일을 잃어버리거나 마음을 바꾸면

- 후보
  - 되돌릴 수 없게 한다
  - 관리자 PIN으로 넘기기를 취소한다
- 고른 것: 넘기기 취소
- 이유: USB를 잃어버리거나 새 PC 준비가 늦어지면 옛 PC를 다시 써야 한다. "다른 PC에서 이미 시작했다면 취소하지 마세요"를 경고한다. 취소해도 세대 번호는 올리지 않는다. 올리면 이미 넘겨받은 새 호스트보다 옛 호스트가 최신으로 보인다.
- 넘기는 중 화면에서 저장하기 전에 [넘기지 않고 돌아가기]를 누를 때는 PIN을 묻지 않는다. 아직 아무 데도 넘기지 않았다.

## 새 PC에서 누가 넘겨받나

- 후보
  - 아무나
  - 넘기기 파일 안의 관리자 이름과 PIN으로 확인
- 고른 것: 파일 안 관리자의 PIN
- 이유: 옛 호스트는 꺼져 있어 물어볼 곳이 없다. 파일 안의 관리자 계정으로 확인해 다른 직원이 실수로 호스트를 바꾸는 일을 막는다. 파일을 가진 사람은 PIN 없이도 내용을 열 수 있어서, 이 확인은 실수를 막는 장치이고 파일을 지키는 장치는 아니다. 그래서 틀린 횟수를 세지 않는다. (원리만)

## 다른 PC가 옛 호스트에 다시 붙으면

- 후보
  - 경고만 한다
  - 막고 주소를 다시 넣게 한다
- 고른 것: 막는다
- 이유: 데이터마다 묶음 ID와 세대 번호를 두고, 넘겨받을 때마다 세대 번호를 올린다. 접속 PC는 승인받아 이어진 호스트의 세대 번호를 기억하고, 그보다 낮은 호스트에는 붙지 않는다. 경고를 누르고 넘어가면 옛 호스트에 접수가 들어간다. (테스트로 확인)
- 묶음 ID가 다른 호스트(예: 백업 없이 새로 설치한 호스트)는 막되 [이 호스트에 새로 승인 요청]을 둔다. 그 호스트의 관리자가 다시 승인해야 붙어서 엉뚱한 호스트에 실수로 붙지는 않는다.
- 호스트는 승인받은 뒤에만 기억한다. 처음 넣은 주소가 엉뚱한 호스트였다면 맞는 호스트까지 막게 되기 때문이다.

## 기기 승인은 다시 받나

- 후보
  - 새 호스트에서 모든 PC를 다시 승인
  - 승인도 데이터와 함께 넘긴다
- 고른 것: 함께 넘긴다
- 이유: 기기 승인은 DB에 있어 넘기기 파일에 들어 있다. PC가 여러 대인 기관에서 다시 승인하는 수고를 던다. 주소만 다시 넣으면 된다.

## 백업으로 되돌리면 넘긴 상태도 돌아가나

- 고른 것: 돌아가지 않는다
- 이유: 넘김 상태는 DB 밖의 실행 모드 파일에 두고, 묶음 ID와 세대 번호는 복원할 때 복원 전 값을 다시 써 넣는다. 넘기기 전 백업으로 되돌려도 옛 세대로 돌아가 다른 PC가 막히는 일이 없다(ADR 0011). (테스트로 확인)
