# 호스트 첫 실행 3단계 기초 정보 미리 넣기 추가 (#122)

처음 배움마루를 설치한 기관 관리자가 관리자 계정을 만들고 복구 코드를 확인한 뒤, 강의실·과목·우선 배정 사유를 이어서 등록할 수 있는 3단계 안내 화면을 추가했다.

- 관련: BR-K11(처음 설정), BR-K12(복구 코드), BR-R1(강의실), BR-J1(과목), BR-S10~S11(우선 배정 사유), ADR 0023. 화면은 처음 설정(`SetupPage`, `RecoveryCodeNotice`, `SetupBasicsPage`).
- 사용자 흐름
  1. `1단계 관리자 계정 만들기`: 관리자 이름과 PIN을 입력해 [관리자 만들기]를 누르면 계정을 만들고 곧바로 관리자 세션을 연다.
  2. `2단계 복구 코드 보관`: 한 번만 보이는 복구 코드를 인쇄하거나 적어 둔 뒤 확인 체크를 하고 [다음]을 누른다.
  3. `3단계 기초 정보 미리 넣기` (선택 단계): `1. 강의실`에서 건물·층을 유지한 채 강의실을 연속 입력하고, `2. 과목 · 우선 배정 사유`에서 과목(분류 유지)과 우선 배정 사유(추천 4개 체크·해제 또는 직접 추가)를 넣는다. 어느 단계에서든 [나중에 하기]나 [설정 마치고 시작하기]를 누르면 이미 열린 관리자 세션으로 메인 화면에 바로 들어간다.
- 알아둘 점
  - 자동 로그인만 실패할 경우에는 복구 코드를 잃어버리지 않고 2단계 확인 뒤 기존 로그인 화면으로 안전하게 넘어간다.
  - 이미 운영 중인 기관의 PIN 복구(`RecoveryPage`) 흐름에서는 3단계를 띄우지 않고 2단계 새 복구 코드 안내 뒤 로그인 화면으로 돌아간다.
  - 학기·강좌·회원은 첫 실행에 넣지 않으며, 시작 후 메인 화면의 각 탭에서 등록한다.
- 웹페이지 안내: 처음 설정 흐름이 2단계에서 3단계(관리자 계정 만들기 -> 복구 코드 보관 -> 기초 정보 미리 넣기)로 바뀌었으므로 PR 8(화면 크기 마무리) 이후 설치·시작 안내 문구와 스크린샷을 함께 갱신한다.

## 첫 실행 3단계에서 기초 정보 API 호출을 위한 관리자 세션을 어떻게 연결하나

- 후보
  - 1단계 관리자 생성 직후 방금 입력한 이름·PIN으로 자동 로그인(`listLoginStaff` -> `login`)해 2단계 복구 코드 보관 -> 3단계 기초 정보 미리 넣기 -> 메인 화면으로 바로 잇는다 (PIN은 즉시 메모리에서 비움)
  - 1단계 -> 2단계 -> 로그인 화면을 거친 뒤, 관리자 첫 로그인 시 강의실·과목·우선 배정 사유가 모두 비어 있으면 1회 안내를 띄운다
- 고른 것: 1단계 직후 자동 로그인으로 3단계 직행 (실패 시 기존 로그인 화면 폴백)
- 이유: 백엔드 API(`/api/setup`)를 바꾸지 않으면서도 1 -> 2 -> 3단계가 로그인 화면에서 끊기지 않고 한 흐름으로 이어진다. 자동 로그인만 실패해도 복구 코드는 그대로 보여 주고 로그인 화면으로 빠지므로 안전하며, PIN 복구 흐름에서는 3단계를 생략해 기존 기관 직원이 불필요한 화면을 보지 않는다. (테스트로 확인)

## 3단계에서 우선 배정 사유를 어떻게 입력하게 하나

- 후보
  - 추천 항목 없이 직접 입력 칸만 둔다
  - 현장에서 자주 쓰는 4개(`직전 학기 반장`, `보훈`, `장애`, `기초생활수급자`)를 미선택 체크박스로 보여 주고, 체크할 때만 `자리 보장`으로 즉시 등록(해제 시 삭제)하며 위 입력 칸으로 직접 추가도 받는다
- 고른 것: 추천 4개 체크박스(`직전 학기 반장` 맨 위) + 직접 추가 입력 칸
- 이유: 소규모 문화·여가 기관에서 가장 흔한 직전 학기 반장과 법정 우선 대상을 한 번 클릭으로 켤 수 있으면서도, 기본값은 모두 꺼져 있어 쓰지 않는 기관의 목록을 어지럽히지 않는다. 각 항목과 강의실·과목은 기존 API로 즉시 저장·삭제하므로 중간에 건너뛰어도 입력한 내용이 유실되지 않는다. (테스트로 확인)
