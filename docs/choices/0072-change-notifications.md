# 다른 PC가 바꾼 내용을 화면에 바로 보여 주기 (#72)

PC 여러 대로 접수하면 한쪽에서 바꾼 내용이 다른 쪽 화면에는 그 화면을 다시 열어야 보였다. 호스트가 저장할 때마다 연결된 화면들에 바뀐 종류를 알리고, 화면이 그 목록을 바로 다시 받게 했다.

- 관련: ADR 0008(HTTP + JSON, SSE 변경 알림)과 그 구현 메모, BR-K8(화면 자동 잠금), BR-K14·K16(기기 승인과 승인 취소). 화면은 메인 화면 위쪽의 "호스트와 연결이 끊겼습니다. 다시 연결하는 중…" 줄
- 사용자 흐름
  1. 접수 노트북에서 회원을 등록하거나 신청을 받는다.
  2. 같은 시각 사무실 PC의 회원 목록, 신청 목록, 신청 수가 저절로 바뀐다. 누를 것은 없다.
  3. 호스트 PC가 꺼지거나 Wi-Fi가 끊기면 화면 위쪽에 빨간 줄이 뜬다. 다시 붙으면 줄이 사라지고 화면이 최신으로 바뀐다.
- 알아둘 점
  - 입력 중인 칸은 바뀌지 않는다. 그사이 다른 PC가 같은 것을 바꿨으면 저장할 때 호스트가 규칙대로 막는다.
  - 어느 PC에서 무엇을 바꿨는지는 알려 주지 않는다. 화면이 조용히 새로 그려진다.
  - 승인을 취소한 PC는 알림 연결이 30초 안에 끊기고, 다음 요청부터 막힌다.
- 웹페이지 안내: 없음

## 알림에 무엇을 담을까

- 후보
  - 바뀐 종류만(회원, 신청 등)
  - 종류와 어느 것(강좌 번호 등)
  - 바뀐 데이터까지
- 고른 것: 종류만
- 이유
  - 데이터를 담지 않으니 회원 정보가 알림으로 흘러 다니지 않는다. 받은 화면이 로그인한 요청으로 다시 받는다.
  - 어느 것까지 담으면 요청은 줄지만, 하나를 빠뜨리면 화면이 낡은 채로 남는다. 직원 몇 명 규모라 종류마다 다시 받아도 된다. (원리만: 요청 수는 재지 않음)

## 화면에 어떻게 보여 줄까

- 후보
  - 목록은 바로 새로 그리고, 입력 중인 칸은 그대로
  - "새 내용이 있습니다" 안내 뒤 직원이 눌러서 새로 그림
- 고른 것: 바로 새로 그림
- 이유: 안내를 누르기 전까지는 낡은 목록과 신청 수를 보고 안내하게 된다. 입력 칸은 화면마다 따로 들고 있어서 목록을 다시 받아도 지워지지 않는다. (원리만: 화면마다 확인하지 않음)

## 연결이 끊기면

- 후보
  - 위쪽에 알리고 알아서 다시 연결
  - 알리지 않고 다시 연결만
- 고른 것: 위쪽에 알리고 1초, 2초, 5초, 10초 간격으로 다시 연결. 다시 붙으면 보던 데이터를 전부 다시 받는다.
- 이유: 끊긴 동안은 다른 PC의 변경이 안 보인다. 직원이 그 사실을 알아야 낡은 화면을 믿지 않는다. 다시 붙은 뒤 전부 받는 것은 끊긴 동안 놓친 알림을 메우기 위해서다. (테스트로 확인: 서버가 연결을 끝내는 조건. 화면의 다시 연결은 확인하지 않음)

## 누가 알림을 받을까

- 후보
  - 승인된 기기에서 로그인한 직원만
  - 승인된 기기면 로그인 없이도
- 고른 것: 로그인한 직원만. 화면이 잠기거나, 로그아웃하거나, 기기 승인이 취소되면 연결을 끊는다.
- 이유: 알림에 데이터는 없어도 언제 무엇이 바뀌는지는 업무 정보다. 다른 요청과 같은 기준으로 맞췄다. 열려 있는 연결은 호스트가 30초마다 세션과 기기 승인을 다시 본다. (테스트로 확인)

## 자동 잠금과 알림

- 후보
  - 알림 때문에 생긴 요청도 직원의 요청으로 센다
  - 직원이 화면을 만지지 않는 동안의 요청은 세지 않는다
- 고른 것: 세지 않는다(BR-K8 문구를 바꿈). 직원이 마지막으로 누르거나 입력한 뒤 10초가 지나면, 그 뒤의 요청은 조용한 요청으로 보낸다.
- 이유
  - 세면 다른 PC가 바쁠 때 자리를 비운 PC가 잠기지 않는다. 회원 명단이 열린 채로 남는다.
  - "알림 때문에 생긴 요청"을 하나하나 표시하는 방법은 화면 라이브러리의 안쪽 동작에 기대야 해서 깨지기 쉽다. 직원이 화면을 만지는지로 가리면 단순하다. (테스트로 확인: 조용한 요청은 호스트와 화면 모두 잠금 시간을 늘리지 않음)

## 서버에서 알림을 어디서 보낼까

- 후보
  - 처리 함수마다 알림 보내기
  - 주소를 등록할 때 바꾸는 종류를 붙여 두고, 읽기가 아닌 요청이 성공하면 알리기
- 고른 것: 주소에 붙이기
- 이유: 처리 함수 스물몇 개에 넣으면 빠뜨리기 쉽다. 주소 바로 옆에 두면 새 주소를 만들 때 함께 보인다. 실패한 요청은 저장한 것이 없으니 알리지 않는다. (테스트로 확인)
