# 화면 크기별 비율 마무리, CSS 토큰 정리, 구버전 부품 제거 (#124)

사무실 노트북과 모니터 해상도·Windows 배율 차이에 맞춰 3구간 화면 크기 기준을 토큰에 반영하고, 전체 화면 CSS 변수 오타를 바로잡아 자동 검증을 붙였으며, 개편 뒤 쓰지 않는 구버전 부품·스타일 파일을 정리했다.

- 관련: ADR 0012(디자인 토큰 단일화), ADR 0023(화면 폴더 구조), #107~#123 화면 개편 작업 마무리.
- 사용자 흐름
  1. 낮은 노트북 화면(`1366×768 100%`, `1920×1080 150%`, `2560×1600 200%` 등 `높이 720px` 이하): 입력·버튼 높이와 바깥 여백을 컴팩트하게 줄여 한 화면에 안 잘리게 한다.
  2. 표준 사무용 노트북(`1920×1080 125%`, `1920×1200 125%` 등): 기존 `16px / 44px` 기본 토큰으로 동작한다.
  3. 넓은 데스크톱 모니터(`1920×1080 100%`, `2560×1600 150%` 등 `폭 1600px` 이상이면서 `높이 860px` 이상): 글자·입력 높이·여백을 한 단계 키우고(`17px / 48px / 36px`), 사이드바와 좌우 분할 카드 폭을 넓혀 빈 공간을 줄인다.
- 알아둘 점
  - 데스크톱 설치형 프로그램 특성과 개인정보 보호를 고려해 모바일·태블릿 전용 화면은 지원하지 않는다.
  - 화면 크기 조정은 모두 `global.css` 토큰 한곳에 모여 있어, 실제 기관 도입 뒤 피드백에 따라 수치만 손쉽게 조절할 수 있다.
- 웹페이지 안내: 화면 개편(PR 0~PR 8)이 모두 완료되었으므로 `just seed` 더미 데이터로 전체 사용 안내 문구와 스크린샷을 일괄 갱신할 수 있다.

## 다양한 사무용 노트북·모니터 해상도를 어떤 기준으로 나누나

- 후보
  - 글자·부품 크기는 고정하고 카드·표 폭 비율만 넓힌다
  - `rem` 기반으로 화면 폭에 비례해 전체를 등비 확대한다
  - CSS 픽셀 기준으로 3구간(`높이 720px 이하` 컴팩트 / 표준 / `폭 1600px 이상 AND 높이 860px 이상` 한 단계 확대)으로 나눈다
- 고른 것: 3구간 기준 (넓은 화면은 폭·높이 두 조건을 모두 만족할 때만 한 단계 확대)
- 이유: Windows 노트북은 화면 크기에 따라 125%·150%·200% 배율이 이미 적용되어 있어 실제 CSS 픽셀을 환산하면 대부분 3구간에 모인다. 폭과 높이 두 조건을 함께 걸면 OS 배율로 이미 크게 보이는 노트북에서는 이중 확대되지 않고, 100% 배율 24~27인치 모니터나 추첨용 대형 화면에서만 시원하게 커진다. (원리만, 실제 기관 배포 뒤 피드백으로 세부 수치 조정 예정)

## CSS 변수 오타와 구버전 부품을 어떻게 마무리하나

- 후보
  - 눈에 띄는 화면 깨짐만 수동으로 고치고 구버전 파일은 남겨 둔다
  - 전체 CSS 파일의 `var(--...)` 참조를 전수 수정해 테스트(`cssTokens.test.ts`)로 잠그고, 더 이상 쓰지 않는 구버전 부품·스타일 7개 파일을 지운다
- 고른 것: 전수 수정 + 자동 검증 테스트 + 구버전 파일 삭제
- 이유: CSS 변수는 오타가 나도 빌드 오류가 나지 않고 색·테두리가 조용히 투명해진다. 자동 검증 테스트를 두면 앞으로 새 화면을 붙일 때도 같은 실수가 CI에서 바로 걸리며, 구버전 `dialog`·`layout`·`table`·`form.module.css`를 지워 두면 새 공통 부품만 쓰게 된다. (테스트로 확인)
