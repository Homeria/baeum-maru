# 다른 PC에서 호스트에 접속하기 (#68)

노트북 두 대로 접수하려면 두 번째 PC가 호스트의 데이터를 같이 써야 한다. 처음 켤 때 이 PC를 호스트로 쓸지 다른 PC에 접속할지 고르게 했다. 접속하는 PC는 호스트 주소를 넣고, 호스트의 관리자에게 승인을 받아야 쓸 수 있다.

- 관련
  - ADR 0001, 0003, 0004, 0007, 0021(실행 모드)
  - 업무 규칙 BR-K13~K17과 역할별 표(기기 승인·거절, 승인한 기기 보기·승인 취소, 실행 모드 바꾸기)
  - 화면: "배움마루 시작하기", "다른 PC에 접속", 직원 관리의 "기기" 탭, 위쪽 알림 줄 "승인을 기다리는 기기가 N대 있습니다"
- 사용자 흐름
  1. 처음 켜면 "이 PC에서 새로 시작"과 "다른 PC에 접속" 중 하나를 고르고 [이렇게 시작]을 누른다. 앱이 다시 켜지고 다음부터는 묻지 않는다.
  2. 호스트 PC에서는 관리자가 직원 관리 > 기기 탭에서 접속 주소(예: `192.168.0.12`)를 본다.
  3. 접속하는 PC에서 그 주소를 넣고 [연결], 이 PC의 이름을 확인하고 [승인 요청]을 누른다. 화면에 승인 번호 6자리가 뜬다.
  4. 호스트 화면 위쪽에 "승인을 기다리는 기기가 1대 있습니다"가 뜬다. [확인하기]를 누르면 같은 번호가 보인다.
  5. 관리자가 두 번호가 같은지 보고 PIN을 넣어 [허락]을 누른다. 접속하는 PC는 로그인 화면으로 넘어간다.
  6. 모드를 바꾸려면 로그인 전 화면 오른쪽 아래의 "…모드로 바꾸기"를 누르고 관리자와 PIN을 넣는다.
- 알아둘 점
  - 이번에는 배움마루 앱을 깐 PC만 접속한다. 휴대폰·브라우저 접속과 자동 찾기(mDNS)는 하지 않았다(ADR 0004, 0007).
  - 다른 PC가 바꾼 내용은 화면을 다시 열어야 보인다. 바로 보여 주는 변경 알림은 다음 작업이다.
  - 호스트 넘기기(데이터를 다른 PC로 옮기기)는 없다. 호스트 PC가 고장 나면 접속 모드 PC를 호스트로 바꿀 수 없다.
  - 통신은 아직 암호화하지 않는다. 7단계에서 한다.
  - 호스트 서버가 같은 네트워크의 다른 PC에 열린다. 방화벽 규칙은 앱이 등록하지 않고, 처음 켤 때 Windows가 묻는 창으로 허용한다. (원리만: Windows에서 확인하지 않음)
- 웹페이지 안내
  - 설치 안내: 처음 켤 때 실행 모드 고르기 화면 추가
  - 사용 안내: 다른 PC 접속(호스트 주소 넣기, 기기 승인 받기) 추가

## 호스트로 켤지 접속할지 언제 고를까

- 후보
  - 켤 때마다 고른다(게임의 "서버 열기 / 들어가기"처럼)
  - 처음 한 번 고르고 기억한다
  - 처음 한 번 고르고 기억하되, 시작 화면에 바꾸기 버튼을 둔다
- 고른 것: 처음 한 번 고르고 기억, 로그인 전 화면에 바꾸기 버튼
- 이유
  - 켤 때마다 고르면 잘못 누른 PC에 빈 데이터가 하나 더 생긴다. 그 PC로 받은 신청은 진짜 호스트에 들어가지 않아 명단이 갈라진다.
  - 이미 데이터가 있는 PC는 묻지 않고 호스트로 켠다. 지금까지 쓰던 PC가 업데이트 뒤에 질문을 받지 않게. (테스트로 확인)

## 모드를 바꿀 때 무엇을 확인할까

- 후보
  - 확인 창만
  - 관리자 이름과 PIN
- 고른 것: 관리자 이름과 PIN. 접속 모드 PC는 직원 계정이 없어 호스트에 물어 확인한다.
- 이유
  - 확인 창은 경고를 읽지 않고 누를 수 있다.
  - 지킬 데이터가 아직 없을 때는 PIN 없이 바꾼다: 직원이 하나도 없는 호스트(처음 설정 화면), 한 번도 승인받지 않은 접속 모드 PC. 승인받기 전 PC는 호스트가 요청을 받아 주지 않아 PIN을 물을 길이 없고, 처음 고르기 실수를 되돌리는 것과 같다.
  - 직원의 실수를 막는 장치다. 그 PC를 마음대로 다루는 사람까지 막지는 않는다. 설정 파일을 직접 고칠 수 있다. (원리만)

## 모드를 바꾸면 그 PC의 데이터는

- 후보
  - 지운다
  - 그대로 두고 쓰지 않는다
- 고른 것: 그대로 둔다. 접속 화면에 "이 PC에 이전 데이터가 남아 있습니다"를 알린다.
- 이유: 잘못 바꿨을 때 다시 호스트로 바꾸면 그 데이터로 돌아온다. 회원 정보가 든 파일을 앱이 몰래 지우지도 않는다. (테스트로 확인: 접속 모드로 바꿔도 DB 파일이 남고 모드는 접속으로 읽힘)

## 호스트에 닿지 않을 때

- 후보
  - 안내하고 [다시 시도], [주소 다시 입력]만
  - 위에 더해 "이 PC를 호스트로 쓰기"
- 고른 것: 안내와 두 버튼만
- 이유: 호스트가 꺼진 것은 대개 잠깐이다. 그때 다른 PC가 호스트가 되면 데이터가 갈라지는 피해가 더 크다.

## 새 PC의 승인을 어떻게 확인할까

- 후보
  - 두 화면에 같은 번호를 띄우고 관리자가 견준 뒤 호스트에서 허락
  - 호스트 화면의 번호를 새 PC에 입력
- 고른 것: 두 화면의 번호를 견주고 호스트에서 관리자 PIN으로 허락
- 이유
  - 새 PC에서 입력할 것이 없어 어르신 직원도 쉽다.
  - 이용자용 Wi-Fi의 다른 기기가 비슷한 이름으로 요청해도, 번호가 다르면 관리자가 알아챈다.
  - 승인받지 않은 기기는 승인 요청과 버전 확인 말고는 아무것도 못 한다. 로그인 화면의 직원 목록도 못 본다. (테스트로 확인)

## 누가, 어디서 허락할까

- 후보
  - 관리자만, 호스트 PC에서만
  - 호스트에 로그인한 직원 누구나
- 고른 것: 관리자만 호스트 PC에서 허락·거절한다. 승인한 기기 목록과 승인 취소는 관리자가 어느 PC에서나 한다.
- 이유
  - 임시 직원이 새 기기를 들이면 회원 명단에 닿는 길이 늘어난다.
  - 승인 취소는 급할 수 있다(노트북 분실 등). 취소된 기기는 다음 요청부터 막힌다. (테스트로 확인)
  - 승인 번호는 5분 동안만 유효하다. 기다리는 요청은 한 번에 5개까지만 받는다. 같은 Wi-Fi의 누군가가 요청을 쏟아내도 호스트 화면이 덮이지 않게. (테스트로 확인)

## 승인 요청 알림을 어떻게 띄울까

- 후보
  - 호스트 화면이 몇 초마다 서버에 묻는다
  - 호스트 화면이 몇 초마다 그 PC의 앱에 수만 묻고, 수가 바뀔 때만 서버에서 목록을 받는다
- 고른 것: 앱에 수를 묻는다(5초마다)
- 이유: 서버에 자주 물으면 "마지막으로 쓴 때"가 계속 새로워져서 10분 자동 화면 잠금(BR-K8)이 걸리지 않는다. 앱에 묻는 것은 로그인 세션과 상관없다. (원리만)

## 호스트 주소를 어떻게 찾아 보여 줄까

- 후보
  - 네트워크 장치를 모두 훑는 라이브러리를 더한다
  - 운영체제에 "바깥으로 나갈 때 쓸 이 PC의 주소"를 묻는다(새 라이브러리 없음)
- 고른 것: 운영체제에 묻는다
- 이유: 라이브러리를 늘리지 않는다. 다만 공유기에 바깥으로 나가는 길이 없는 네트워크에서는 못 찾을 수 있다. 그때는 "주소를 찾지 못했습니다"를 띄운다. (원리만: 여러 네트워크에서 확인하지 않음)

## 접속하는 PC는 무엇을 기억할까

- 후보
  - 호스트 주소만
  - 호스트 주소와 기기 증표
- 고른 것: 둘 다 데이터 폴더에 기억한다. 승인을 기다리는 중이면 승인 번호도 기억해서, 앱을 껐다 켜도 기다리던 요청을 이어 본다.
- 이유
  - 기기 증표가 없으면 켤 때마다 다시 승인받아야 한다.
  - 증표는 그 PC에 그대로 들어 있다. 그 PC에 손댈 수 있는 사람이 빼내면 흉내 낼 수 있다. ADR 0007에서 감수하기로 했고 7단계에서 보강한다.
  - 호스트 주소를 바꿔 넣어도 증표는 버리지 않는다. 호스트 PC의 주소만 바뀐 경우가 많다. 다른 호스트면 그 호스트가 모르는 증표라서 다시 승인을 요청하게 된다. (테스트로 확인)
