# 용어집

배움마루에서 쓰는 업무 용어와 코드 이름의 대응표다. 문서, 화면, 코드는 이 표의 말을 쓴다. 새 용어가 필요하면 코드보다 먼저 여기에 추가한다.

- **한국어**는 화면과 문서에 쓰는 말이다.
- **영어**는 코드에서 쓰는 이름이다.
- 기관마다 부르는 말이 다른 경우는 [다른 이름](#다른-이름)에 모아 두었다. 화면 표시 이름을 바꾸는 설정은 나중에 검토한다.

## 운영

| 한국어 | 영어 | 뜻 |
|---|---|---|
| 기관 | `Organization` | 배움마루를 쓰는 센터나 복지관 한 곳 |
| 학기 | `Term` | 모집, 선발, 수업을 함께 진행하는 기간 (예: 2027년 1학기) |
| 기초 정보 | `ReferenceData` | 학기가 바뀌어도 이어지는 목록. 과목, 강의실, 강사처럼 한 번 등록해 두고 강좌를 열 때 고른다. 화면에서는 한 탭에 모은다 |

## 강좌

강좌는 **분류 > 과목 > 수준 > 반**의 4단계로 정리한다. 수준과 반은 과목에 따라 없을 수 있다.

```text
분류: 평생교육
└─ 과목: 스마트폰
   ├─ 수준: 초급 ─┬─ 1반   ← 강좌
   │              └─ 2반   ← 강좌
   └─ 수준: 중급 ─── 1반   ← 강좌
```

| 한국어 | 영어 | 뜻 |
|---|---|---|
| 분류 | `category` | 과목을 묶는 큰 갈래 (예: 평생교육, 취미여가). 과목의 칸이다. 선택이고, 분류를 쓰는 과목이 없으면 화면에서 감춘다 |
| 과목 | `Subject` | 무엇을 배우는지 (예: 스마트폰, 요가). 학기가 바뀌어도 이어진다 |
| 수준 | `Level` | 같은 과목 안의 난이도 (예: 초급, 중급). 선택 |
| 반 | `Section` | 같은 과목, 같은 수준을 나눠 여는 단위 (예: 1반, 2반). 선택 |
| 강좌 | `Course` | 한 학기에 실제로 열려서 **신청을 받는 단위**. 과목, 수준, 반의 조합이다 (예: 2027년 1학기 스마트폰 초급 1반) |
| 정원 | `Capacity` | 강좌가 받을 수 있는 인원 |
| 수업 시간 | `Schedule` | 요일, 시작·종료 시각, 강의실. 주 2회 강좌는 수업 시간이 두 개고, 요일마다 강의실이 다를 수 있다 |
| 강의실 | `Room` | 수업하는 장소 (예: 3층 다목적실). 한 번 등록해 두고 강좌의 수업 시간마다 고른다 |
| 건물 | `building` | 강의실이 있는 건물 (예: 본관, 별관). 강의실의 칸이다. 기본값은 본관이고, 건물이 하나뿐인 기관은 화면에서 감춘다 |
| 층 | `floor` | 강의실이 있는 층. 지하 2층부터 5층까지 고른다. 선택 |
| 강사 | `Instructor` | 강좌를 가르치는 사람 |

## 회원

| 한국어 | 영어 | 뜻 |
|---|---|---|
| 회원 | `Member` | 강좌를 신청하는 이용자. 한 번 등록하면 학기가 바뀌어도 이어진다 |
| 회원번호 | `MemberNo` | 기관이 회원에게 붙인 번호. 프로그램 내부에서 쓰는 식별자와는 따로 둔다 |
| 이름 | `MemberName` | 회원의 이름. 필수 |
| 연락처 | `PhoneNumber` | 휴대폰이나 집 전화번호. 필수. 대기자 승격 때 연락한다 |
| 생년월일 | `birth_date` | 선택 |
| 성별 | `Gender` (`Male` 남, `Female` 여) | 선택 |
| 수강 이력 | (계산) | 회원이 지난 학기에 수강한 강좌 목록. 따로 저장하지 않고 확정된 신청(확정 단계를 끈 기관은 당첨된 신청)에서 계산한다 |

## 신청

| 한국어 | 영어 | 뜻 |
|---|---|---|
| 신청 | `Application` | 회원 한 명이 강좌 하나에 낸 신청. 강좌 4개를 신청하면 신청은 4건이다 |
| 접수 | (동작) | 창구에서 회원 한 명의 신청 여러 건을 한 번에 입력하는 일. 접수 자체는 따로 저장하지 않는다 |
| 신청 규칙 | `ApplicationRule` | 신청을 받을 때 확인하는 조건. [신청 규칙 종류](#신청-규칙-종류) 참고 |
| 삭제 기록 | `DeletionRecord` | 선발 전에 삭제한 신청에 대한 기록. 신청은 지워지고 누가, 언제, 무엇을 지웠는지만 남는다 |
| 규칙 예외 | `RuleOverride` | 신청 규칙을 어긴 신청을 직원이 사유를 적고 받아준 기록 |
| 추가 신청 | (신청의 한 종류) | 선발 마감 뒤 자리가 남은 강좌에 받는 신청 |

### 신청 규칙 종류

| 한국어 | 뜻 |
|---|---|
| 시간 겹침 금지 | 수업 시간이 하나라도 겹치는 강좌는 함께 신청할 수 없다 |
| 같은 과목 중복 금지 | 같은 과목은 수준이나 반이 달라도 하나만 신청할 수 있다 |
| 최대 신청 개수 | 한 회원이 한 학기에 신청할 수 있는 강좌 수 |

## 선발

| 한국어 | 영어 | 뜻 |
|---|---|---|
| 선발 | `Selection` | 신청자 가운데 정원만큼 당첨자를 정하는 일 |
| 선발 방식 | `SelectionMethod` | 추첨 또는 선착순 |
| 추첨 | `Lottery` | 무작위로 당첨자와 대기 순번을 정하는 선발 방식 |
| 선착순 | `FirstCome` | 신청 순서대로 당첨자를 정하는 선발 방식 |
| 전원 당첨 | (선발 결과) | 신청자가 정원 이하일 때 선발 없이 모두 당첨으로 처리하는 것 |
| 우선 배정 | (선발 단계) | 선발 전에 일부 신청자에게 자리를 먼저 주는 것. 남은 자리만 선발한다 |
| 우선 배정 사유 | `PriorityReason` | 우선 배정을 받는 이유 (예: 지난 학기 반장, 장애인 우대). 기관이 목록을 만들고, 직원이 신청마다 붙인다 |
| 배정 방식 | `PriorityMethod` | 우선 배정 사유가 자리를 어떻게 받는지. 사유마다 하나다. 지금은 자리 보장뿐이다 |
| 자리 보장 | `Guaranteed` | 배정 방식의 하나. 선발 없이 당첨되고 정원에 들어간다. 남은 자리만 선발한다 |
| 선발 마감 | (강좌의 상태) | 강좌의 선발 결과를 최종으로 굳히는 것. 마감 뒤에는 다시 추첨할 수 없고, 포기와 승격을 받는다 |
| 선발 결과 | `SelectionResult` | 마감한 강좌의 당첨자, 대기자, 포기한 사람. 포기와 승격을 처리하는 탭 이름이기도 하다 |
| 추첨 기록 | `LotteryRun` | 한 번의 추첨에 대한 기록. 시각, 대상, 난수 시드를 남겨 같은 결과를 다시 만들어 볼 수 있다 |

## 신청 상태

```text
접수됨 ─┬─> 당첨 ───> 확정
        ├─> 대기 ──> (승격) ──> 당첨
        └─> 탈락

당첨, 대기는 포기로 바뀔 수 있다. 선발 전(접수됨) 신청은 포기 대신 삭제한다.
```

| 한국어 | 영어 | 뜻 |
|---|---|---|
| 접수됨 | `Submitted` | 신청을 받았고 아직 선발 전 |
| 당첨 | `Selected` | 선발이나 우선 배정으로 자리를 받음. 추첨은 실력이 아니라 운으로 정해지므로, 떨어진 사람이 부족해서 떨어진 것처럼 들리는 '합격' 대신 쓴다. 현장 공지도 '당첨자'라고 쓴다 |
| 대기 | `Waitlisted` | 떨어졌지만 대기 순번을 받음 |
| 탈락 | `Rejected` | 떨어졌고 대기 순번도 없음. 대기자 수에 상한을 둔 경우에만 생긴다 |
| 확정 | `Confirmed` | 당첨 뒤 수강하기로 최종 확인됨. 확정 단계를 켠 기관에서만 쓴다 |
| 포기 | `Withdrawn` | 선발 뒤, 확정 전에 수강하지 않기로 함. 확정 뒤에 그만두는 중도 포기는 첫 버전에서 다루지 않는다 |

## 대기자

| 한국어 | 영어 | 뜻 |
|---|---|---|
| 대기 순번 | `WaitlistPosition` | 대기자 사이의 순서. 추첨 때 받은 번호를 그대로 쓴다. 앞사람이 빠져도 바뀌지 않는다 |
| 빈자리 | `OpenSeats` | 정원에서 당첨 수를 뺀 것. 당첨자가 포기하면 생긴다 |
| 연락할 차례 | `ContactTurn` | 빈자리를 채우려고 지금 연락할 대기자. 대기 순번 앞에서부터 빈자리 수만큼이고, 연락이 안 된 사람은 건너뛴다. 저장하지 않고 그때그때 정한다 |
| 승격 | `Promotion` | 빈자리가 생겼을 때 대기 순번대로 대기자를 당첨으로 바꾸는 일 |
| 연락 결과 | `ContactResult` | 대기자에게 연락한 결과. 수락(`Accepted`), 거절(`Declined`), 연락 안 됨(`Unreachable`) |
| 연락 기록 | `ContactLog` | 연락 결과를 남긴 기록. 누가, 언제 연락했는지도 남긴다 |
| 잘못 처리 바로잡기 | `WithdrawalCorrection` | 관리자가 잘못 처리한 포기를 사유를 적고 포기 전 상태로 되돌리는 일. 회원의 번복을 받는 기능이 아니다 |
| 선발 결과 변경 기록 | `SelectionChange` | 포기, 연락 결과, 잘못 처리 바로잡기를 쌓는 기록. 고치거나 지우지 않는다 |

## 직원과 접근

로그인 방식은 [ADR 0003](../adr/0003-login-access.md)을 따른다.

| 한국어 | 영어 | 뜻 |
|---|---|---|
| 호스트 | `Host` | 데이터(DB)를 가진 PC. 기관에 한 대뿐이다 |
| 직원 | `Staff` | 배움마루를 쓰는 기관 사람. 계정이 있어야 쓸 수 있다 |
| 역할 | `Role` | 직원이 할 수 있는 일의 범위. 관리자(`Admin`), 직원(`Staff`), 임시 직원(`TempStaff`), 조회 전용(`ReadOnly`) |
| PIN | `Pin` | 직원 확인에 쓰는 짧은 숫자 |
| 기기 | `Device` | 호스트에 접속하는 PC나 휴대폰 |
| 기기 승인 | `DeviceApproval` | 새 기기가 접속을 요청하고 호스트에서 허락하는 일 |
| 승인 번호 | `ApprovalCode` | 기기 승인 때 호스트 화면에 뜨는 일회용 번호 |
| 복구 코드 | `RecoveryCode` | 관리자가 PIN을 잊었을 때 쓰는 코드. 처음 설치할 때 만들어 인쇄해 둔다 |
| 접속 기록 | `AccessLog` | 누가, 언제, 어느 기기에서 로그인했는지. 로그인 실패, 로그아웃, 잠금 풀기 실패, 복구 코드 사용도 남긴다 |
| 유효기간 | `valid_until` | 직원 계정을 쓸 수 있는 마지막 날. 그날까지 로그인할 수 있다. 임시 직원은 반드시 있다 |
| 사용 중지 | `disabled` | 직원 계정을 지우지 않고 로그인만 막은 상태. 다시 사용하게 할 수 있다 |
| 세션 | `Session` | 로그인해서 다음 로그아웃까지 이어지는 상태. 호스트가 증표(토큰)를 주고, 앱은 요청마다 그 증표를 싣는다 |
| 화면 잠금 | `ScreenLock` | 한동안 요청이 없어 세션이 잠긴 상태. 같은 직원의 PIN으로 연다 |
| 계정 잠금 | `AccountLock` | PIN을 여러 번 틀려 그 계정의 로그인을 잠시 막은 상태 |
| PIN 초기화 | `PinReset` | 관리자가 직원의 PIN을 새로 정해 주는 일 |

## 다른 이름

기관에 따라 아래처럼 부르기도 한다. 배움마루 안에서는 왼쪽 말을 쓴다.

| 배움마루 | 다른 기관에서 쓰는 말 |
|---|---|
| 학기 | 기, 기수, 분기 |
| 분류 | 영역, 분야, 과정군 |
| 수준 | 급, 단계, 과정 (입문·초급·중급) |
| 강좌 | 프로그램, 과정, 교실 |
| 당첨 | 합격, 선정 |
| 확정 | 등록, 수강 확정 |
| 자리 보장 | 우선 신청권 |
