# 0020. 앱 검사는 작업 셋으로 나눠 함께 돌린다

- 상태: 채택 (2026-11-23)
- 근거: [0012](0012-skeleton.md)
- 대체: 0012의 "CI도 `just check`를 쓴다"

## 상황

0012에서 검사는 명령 하나(`just check`)로 하고 CI도 같은 명령을 쓰기로 했다. 그래서 앱 검사(`check.yml`)는 작업(job) 하나에서 모든 검사를 순서대로 돌렸다.

2026-11-23에 "Tauri 시스템 패키지" 단계(apt로 WebKit 등을 받는 단계)가 평소 20초대에서 5분 넘게 걸렸다(#61, #63). GitHub Actions 자체는 정상이었고, 이 단계만 느렸다. Ubuntu 미러에서 받는 속도가 느렸던 것으로 본다(원인은 확인하지 못함).

이 패키지가 필요한 것은 Rust 컴파일뿐이다. 그런데 화면 검사와 의존성 검사(cargo-deny)도 같은 작업 안에 있어서 이 단계를 기다렸다. 같은 날 cookie 취약점으로 cargo-deny가 실패했을 때도, 그 결과를 보려면 apt와 Rust 컴파일을 다 기다려야 했다.

## 선택지

**나누기**

1. 작업 하나 그대로, 캐시만 붙인다: 0012를 바꾸지 않는다. 다른 검사가 apt를 계속 기다린다.
2. 작업 둘: apt가 필요 없는 쪽(이름, 화면, 의존성)과 Rust 쪽
3. **작업 셋: 화면(이름 포함), 의존성, Rust**

**apt 패키지를 빨리 받는 방법**

1. 캐시 액션(`awalsh128/cache-apt-pkgs-action`): 설치한 파일을 캐시에 담고, 다음부터는 미러에 가지 않고 풀어 놓는다.
2. 공식 `actions/cache`로 받은 `.deb` 파일만 보관한다: 외부 액션이 없다. 다만 `apt-get update`는 여전히 미러에 가서, 미러가 느리면 여전히 느리다.
3. 빠른 미러를 골라 주는 액션: 캐시가 없어 매번 받는다.
4. **캐시 없이 `apt-get`에 재시도만 붙인다**: 미러가 느린 날의 대기는 남는다.

처음에는 1을 골랐다. 이 PR의 첫 실행에서 문제가 드러나 4로 바꿨다.

- 미러가 파일 두 개를 404로 돌려줘 설치가 실패했는데, 액션은 성공으로 끝났다. 원인이 로그 안쪽에 묻히고, 다음 단계(Rust 컴파일)에서 엉뚱한 오류로 터졌다.
- 그 상태로 빈 캐시를 저장했다. 같은 키로 다시 돌리면 빈 캐시를 복원하고 설치를 건너뛰어 계속 실패한다.
- 실행 중에 다른 저장소의 `master`에서 스크립트(apt-fast)를 받아 `sudo`로 돌린다. 판이 고정되지 않아, 그 저장소가 바뀌면 우리 CI에서 무엇이든 돌 수 있다.

## 결정

**작업 셋으로 나누고, Rust 작업의 apt 패키지는 캐시 없이 `apt-get`에 재시도(`Acquire::Retries=3`)를 붙여 받는다.**

| 작업 | 검사 |
|---|---|
| 화면 | `just check-names`, `just check-ui` |
| 의존성 | `just check-deps` |
| Rust | `just check-rust`, `just check-bindings` |

- 내 PC에서는 지금처럼 `just check` 하나로 전부 검사한다. CI는 그 안의 하위 명령을 작업별로 부른다. 검사 내용은 같다.
- 경로 조건(문서만 바뀌면 돌지 않음)은 그대로다.
- 설치가 실패하면 그 단계에서 바로 실패한다.
- apt 캐시는 미러가 느린 날이 잦아지면 다시 본다. 그때도 설치 실패를 숨기지 않고 외부 스크립트를 받지 않는 방법이어야 한다.

## 이유

- 셋으로 나누면 화면과 의존성 검사는 apt와 Rust 컴파일을 기다리지 않고 바로 결과가 나온다.
- 검사 결과가 틀리지 않는 것이 빠른 것보다 중요하다. 설치 실패를 성공으로 넘기는 도구는 쓰지 않는다.
- 미러가 느렸던 것은 하루 일이었다. 재시도는 잠깐 어긋나거나 끊긴 경우를 넘긴다.
- 전체 완료 시간은 여전히 Rust 작업이 정한다. 미러가 느린 날에는 Rust 결과만 늦게 나온다.

## 결과

**좋은 점**
- 화면과 의존성 쪽 실패를 빨리 본다.
- 외부 액션이 늘지 않는다.

**감수할 점**
- 미러가 느린 날에는 Rust 작업이 여전히 느리다.
- 작업마다 저장소를 받고 도구를 설치하므로, 모든 작업의 실행 시간을 더하면 전보다 길다.
- 나중에 main 보호에서 필수 검사를 켜면 작업 이름 셋을 모두 넣어야 한다.
