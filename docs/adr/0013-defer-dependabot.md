# 0013. Dependabot 버전 업데이트는 출시 준비 때 붙인다

- 상태: 채택 (2026-11-15)
- 근거: [0012](0012-skeleton.md)

## 상황

0012에서 Dependabot이 한 달에 한 번 Rust·npm·GitHub Actions 업데이트 PR을 만들게 했다. 뼈대를 합치자마자 메이저 업데이트 PR이 올라왔고, 검사에서 깨졌다(#9, #12, #13). TypeScript 7은 typescript-eslint가 아직 지원하지 않는다.

지금은 개발 초반이다. 기능 코드가 거의 없고 회원 데이터를 다루는 코드도 없다. 깨지는 PR을 매달 닫는 일이 업데이트로 얻는 것보다 크다.

## 선택지

1. 0012대로 둔다. 메이저는 무시 댓글로 하나씩 정리한다.
2. 메이저는 받지 않고 마이너·패치 묶음만 받는다.
3. **버전 업데이트를 출시 준비(7단계)까지 미룬다.**

## 결정

**3번.**

- `.github/dependabot.yml`을 두지 않는다. 7단계에서 다시 넣는다. 그때 메이저를 묶음에서 뺄지(2번)도 정한다.
- 보안 알림은 켜 둔다. 취약점이 알려지면 Security 탭에 알림이 온다.
- 보안 업데이트 자동 PR은 7단계에서 같이 켠다.
- cargo-deny는 0012대로 `just check`에서 돈다.
- 그 사이 의존성은 기능을 만들다 필요할 때 직접 올린다.

## 이유

- 출시 전에는 업데이트가 늦어도 영향을 받는 사용자가 없다.
- 위험한 취약점은 보안 알림과 cargo-deny로 알 수 있다.
- 출시 준비 때는 회원 데이터를 다루는 코드가 있어서 업데이트를 챙길 이유가 분명해진다.

## 결과

**감수할 점**
- 7단계에서 그동안 쌓인 업데이트를 한꺼번에 올려야 한다.
- 보안 알림은 알려 주기만 하고 고치는 PR은 만들지 않는다. 알림이 오면 직접 올린다.
