# 0004. 호스트 찾기: 주소 입력 + 기억, 자동 찾기는 나중

- 상태: 채택 (2026-11-14)
- 근거: [실험 04](../../spikes/03-tauri-ime-lan/), [실험 05 보류](../../spikes/README.md), [0001](0001-app-form.md)

## 상황

접속하는 PC의 앱과 휴대폰 브라우저는 호스트 PC의 주소를 알아야 한다. 많은 기관에서 PC 주소는 공유기가 그때그때 나눠 주기 때문에(동적 IP) 바뀔 수 있다.

- 실험 04: 호스트 화면에 뜬 주소(`http://192.168.x.x:47800`)를 입력해 접속할 수 있었다.
- 실험 05(자동 찾기, mDNS): PC가 한 대뿐이라 확인하지 못했다.

## 선택지

1. **주소 입력 + 기억**: 처음 한 번 입력하면 앱이 기억한다. 자동 찾기는 확인 뒤에 더한다.
2. **같은 네트워크를 훑어서 찾기**: 주소 254개에 차례로 물어본다. 보안 프로그램이 공격으로 오해할 수 있다.
3. **자동 찾기(mDNS)를 기본으로**: 가장 편하지만 기관 네트워크에서 될지 확인하지 못했다.

## 결정

**1번.**

- 호스트 화면에 접속 주소를 크게 보여준다. 휴대폰용 QR 코드도 함께 보여준다.
- 접속하는 앱은 처음 한 번 주소를 입력받고 기억한다.
- 연결이 안 되면 "호스트 주소가 바뀌었을 수 있습니다"라고 안내하고 다시 입력받는다.
- **포트는 47800으로 고정한다.** 직원은 주소만 입력하면 되고, 방화벽 규칙도 하나로 정해진다. 47800을 다른 프로그램이 쓰고 있으면 호스트가 시작하지 않고 그 사실을 알린다.
- 자동 찾기(mDNS)는 실험 05를 마친 뒤 편의 기능으로 더한다. 자동 찾기가 되더라도 주소 입력은 계속 남긴다.

## 이유

- 확인된 방법만 기본으로 삼는다. 자동 찾기가 안 되는 네트워크에서도 주소 입력은 늘 된다.
- 대상 기관은 PC가 몇 대뿐이라 처음 한 번 입력하는 부담이 작다.

## 결과

**감수할 점**
- 호스트 PC의 주소가 바뀌면 다른 PC에서 다시 입력해야 한다. 공유기에서 호스트 PC 주소를 고정하는 방법(DHCP 예약)을 설치 안내서에 넣는다.

**나중에 할 것**
