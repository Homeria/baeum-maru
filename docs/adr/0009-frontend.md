# 0009. 화면 기술: React + Vite

- 상태: 채택 (2026-11-14)
- 근거: [실험 06](../../spikes/06-frontend-react-svelte/), [0007](0007-app-only-access.md), [0008](0008-http-json-sse.md)

## 상황

화면은 앱 창(WebView2) 안의 웹 페이지다(0007). 화면은 서버에 HTTP로 요청하고, SSE 알림을 받으면 목록을 다시 받아 새로 그린다(0008).

기관 PC는 오래된 경우가 많다. 유지보수자의 기준은 두 가지다.

- **가벼움**: 빌드한 화면 파일의 크기
- **안정성**: 버벅임 없이 동작하는가

## 선택지

1. **React**: 가장 널리 쓰이는 화면 도구. 자료, 부품, AI 도움이 많다.
2. Svelte: 더 작고 빠르다. 2024년 Svelte 5에서 문법이 크게 바뀌었다.

화면 파일은 두 경우 모두 Vite(화면 코드를 묶어 주는 빌드 도구)로 만든다.

## 실험 06 결과

같은 화면(회원 표, 검색, 알림 후 다시 받기)을 두 도구로 만들어 Chrome에서 쟀다.

- **크기**: React 220KB(압축 69KB), Svelte 40KB(압축 16KB). 앱 실행 파일(약 9MB)에 비하면 둘 다 작다.
- **1,000줄을 전부 그릴 때** (CPU 4배 감속으로 오래된 PC 흉내)
  - 검색 최대: React 0.34초, Svelte 0.39초
  - 알림 후 다시 그리기 최대: 둘 다 약 0.06초
  - 첫 화면: React 0.45초, Svelte 0.31초
  - 대부분 브라우저가 줄 위치를 계산하는 시간이라 도구 차이가 거의 없다.
- **차이는 5,000줄처럼 많이 그릴 때만 벌어진다** (검색 최대 React 1.65초, Svelte 1.16초).
- **100줄만 그리면** 회원이 5,000명이어도 두 도구 모두 즉시 반응한다(약 0.04초).

## 결정

- **화면은 React로 만들고 Vite로 빌드한다.**
- **한 번에 그리는 줄 수를 제한한다.** 버벅임을 가르는 것은 도구보다 그리는 줄 수다. 표 하나에 1,000줄을 넘겨 그리지 않는다. 화면별로 몇 줄씩 보여 줄지는 기능 슬라이스(6단계)에서 정한다.
- 다음 내용은 뼈대(5단계)에서 정한다.
  - JavaScript와 TypeScript 중 무엇을 쓸지
  - 화면 파일을 앱에 넣는 방법
  - 부품 라이브러리를 쓸지 여부

## 이유

- 표시 줄 수가 1,000줄 이하인 이 앱에서는 두 도구의 체감 성능이 같았다. 성능은 고를 근거가 되지 않았다.
- 크기 차이(약 180KB)는 앱 전체 크기에 비하면 무시할 만하다.
- 유지보수자가 React를 배운 적이 있고 컴포넌트 개념을 안다. Svelte는 처음이다. Rust를 새로 배우는 중이라 화면까지 새로 배우는 부담을 줄인다.
- 자료와 AI 도움이 많아 막혔을 때 풀기 쉽다.

## 결과

**좋은 점**
- 익숙한 도구라 화면 작업이 빨라진다.
- 막혔을 때 찾을 자료가 많다.

**감수할 점**
- Svelte보다 화면 파일이 약 5배 크고, 첫 화면이 오래된 PC에서 0.1초 정도 늦다.
- React에서 흔한 실수(불필요하게 다시 그리기, `useMemo` 잘못 쓰기)를 조심해야 한다. 줄 수 제한이 큰 버벅임은 막아 준다.
- Windows(WebView2)와 실제 오래된 PC에서는 재지 않았다. 뼈대(5단계)에서 확인한다.
