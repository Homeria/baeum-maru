# 0018. 결과 명단 파일은 받는 PC의 저장 창으로 저장한다

- 상태: 채택 (2026-11-23)
- 근거: [0002](0002-data-owner.md), [0012](0012-skeleton.md), 업무 규칙 BR-P1~P11

## 상황

결과 명단(Excel)은 호스트가 만든다. 데이터가 호스트에만 있기 때문이다(0002). 그런데 파일이 필요한 사람은 내보내기를 누른 PC 앞의 직원이다. 그 PC에 파일을 어떻게 둘지 정해야 한다.

명단에는 연락처, 생년월일 같은 개인정보가 들어갈 수 있다. 저장 위치를 직원이 모르면 파일이 여기저기 남는다. 담당 직원이 어르신 기관의 선생님이라 "파일이 어디 갔는지 모르겠다"는 일도 줄여야 한다.

## 선택지

1. **창 안에서 다운로드**: 브라우저처럼 화면이 파일을 받아 "다운로드" 폴더에 둔다. 의존성이 없다. 다만 Tauri 창(Windows WebView2, Ubuntu WebKitGTK)에서 다운로드가 어떻게 동작하는지 확인하지 않았고, 직원이 저장 위치를 고를 수 없다.
2. **화면이 저장 창을 띄우고 화면이 파일을 쓴다**: Tauri 플러그인 dialog와 fs를 화면(JavaScript)에서 쓴다. Tauri의 흔한 방식이다. 화면에 파일 쓰기 권한을 열어 주게 된다.
3. **앱(Rust)이 저장 창을 띄우고 앱이 파일을 쓴다**: 화면은 호스트에서 받은 파일 내용을 앱 명령 하나에 넘긴다. 앱이 dialog 플러그인으로 저장 창을 띄우고, 고른 곳에 직접 쓴다. 화면에는 파일 쓰기 권한도, 저장 창 권한도 열지 않는다.

## 결정

**선택지 3.**

- 앱에 `tauri-plugin-dialog`를 넣고, 앱 명령 `save_file` 하나를 만든다. 받는 것은 미리 채울 파일 이름과 파일 내용이다.
- 저장 창은 파일 이름(예: `2027년 1학기 게시용 강좌별.xlsx`)을 미리 채우고 Excel 파일(`.xlsx`) 거르개를 둔다. 폴더와 이름은 직원이 고른다.
- 직원이 저장 창을 닫으면 아무것도 쓰지 않고 "저장하지 않았습니다"로 끝난다. 내보내기 기록은 호스트가 파일을 만들 때 이미 남는다(BR-P11). 개인정보가 호스트 밖으로 나간 순간을 기록하는 것이기 때문이다.
- 앞으로 다른 파일 저장(백업 파일 받기 등)도 이 명령을 쓴다.

## 이유

- 화면 코드에 파일 쓰기 권한을 주지 않으면, 화면에 문제가 생겨도 PC의 아무 파일이나 쓰는 일이 막힌다. 개인정보를 다루는 앱이라 권한을 좁게 둔다.
- 직원이 고른 곳에 저장되므로 파일을 찾기 쉽고, 개인정보 파일이 다운로드 폴더에 쌓이지 않는다.
- 앱 쪽 코드는 저장 창 띄우기와 파일 쓰기뿐이라 짧다.

## 결과

**좋은 점**
- 화면은 Tauri 권한 설정 없이 앱 명령 하나만 부른다.
- 저장 창은 각 운영체제의 기본 창이라 직원에게 익숙하다.

**감수할 점**
- 의존성이 늘어난다: `tauri-plugin-dialog`와, 그것이 쓰는 `tauri-plugin-fs`, `rfd`. cargo-deny 검사를 통과해야 한다.
- 파일 내용이 호스트 → 화면 → 앱 명령으로 한 번 더 건너간다. 명단은 크지 않아(수백 줄) 문제되지 않는다.
- 화면 테스트(Vitest)는 Tauri 없이 돌므로 앱 명령 부르기는 테스트용 대역으로 바꿔 시험한다.
- Ubuntu의 저장 창이 어떤 모양으로 뜨는지, Windows에서 한글 파일 이름이 잘 저장되는지는 만들면서 확인한다.
