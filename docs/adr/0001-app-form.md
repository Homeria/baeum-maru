# 0001. 모든 직원 PC에 같은 앱, 웹 접속은 예비

- 상태: 일부 대체됨 ([0007](0007-app-only-access.md): 웹 접속 예비 → 앱으로만 접속)
- 근거: [실험 03·04](../../spikes/03-tauri-ime-lan/)

## 상황

기관에는 직원 PC가 2~4대 정도 있고, 여러 직원이 동시에 접수한다. 처음부터 그린 그림은 "어느 PC든 호스트(데이터를 가진 PC)가 될 수 있고, 호스트가 있으면 다른 PC는 거기에 접속하도록 안내한다"였다.

실험 03·04에서 확인한 것:
- 데스크톱 앱(Tauri) 안에 웹 서버를 띄우고, 같은 Wi-Fi의 다른 기기가 브라우저로 접속할 수 있다.
- Windows의 앱 창(WebView2)에서 한글 입력에 문제가 없다. 직원 PC의 Edge도 같은 엔진이다.
- 서명하지 않은 실행 파일은 설치할 때 Chrome 내려받기 차단, SmartScreen 경고, 방화벽 허용이라는 관문을 지난다.

## 선택지

1. **모든 PC에 앱 + 웹 예비**: 모든 직원 PC에 같은 앱을 설치한다. 앱이 호스트 역할도, 접속 역할도 한다. 앱이 없는 기기는 브라우저로 접속한다.
2. **호스트 PC에만 앱, 나머지는 브라우저**: 설치는 한 번이지만, 호스트를 바꿀 때 새로 설치해야 하고 호스트가 꺼지면 브라우저는 "연결할 수 없음"만 보여준다.
3. **모든 PC에 앱, 웹 접속 없음**: 화면이 한 종류라 단순하지만 휴대폰이나 앱이 없는 PC는 쓸 수 없다.

## 결정

**1번. 모든 직원 PC에 같은 앱을 설치하고, 웹 접속은 예비로 둔다.**

## 이유

- "어느 PC든 호스트가 될 수 있다"는 처음 그림과 가장 잘 맞는다. 어느 PC에나 같은 앱이 있으니 호스트를 바꿀 때 새로 설치할 필요가 없다.
- 앱이 호스트를 찾고, 호스트가 꺼지면 안내하고, 호스트를 넘기는 일을 화면 안에서 처리할 수 있다. 브라우저만으로는 이런 안내를 하기 어렵다.
- 앱 화면을 앱 안 서버가 웹 페이지로 보내 주는 구조라, 웹 접속은 거의 공짜로 따라온다 (실험 04).

## 결과

**좋은 점**
- 모든 PC가 같은 프로그램이라 설명서, 문의 대응, 업데이트가 하나로 끝난다.
- 앱을 못 까는 PC나 휴대폰도 브라우저로 쓸 수 있다.

**감수할 점**
- PC마다 설치 관문(Chrome 차단, SmartScreen, 방화벽)을 한 번씩 지나야 한다. 배포 방식(4단계 8번)과 릴리스(7단계)에서 줄일 방법을 찾는다.
- 웹 예비를 지원하려면 화면과 서버가 브라우저도 알아듣는 방식으로 대화해야 한다 (4단계 6번에 영향).

**나중에 확인할 것**
- 휴대폰 Chrome에서 "Too Many Requests"로 열리지 않았던 문제 (실험 04 남은 확인)
