# 0010. 배포와 업데이트: 설치판 + 완전 포터블판, 서명, 버전 맞추기

- 상태: 채택 (2026-11-14)
- 근거: [실험 03·04](../../spikes/03-tauri-ime-lan/), [0002](0002-data-owner.md), [0004](0004-host-discovery.md), [0005](0005-storage.md), [0007](0007-app-only-access.md)

## 상황

실험 04에서 서명 없는 exe를 받아 실행하기까지 관문이 세 번 있었다.

1. Chrome 다운로드 차단
2. SmartScreen 경고("더 보기 → 실행")
3. 방화벽 허용 창

1과 2는 서명으로 줄어든다. 3은 앱이 47800 포트로 접속을 받기 때문에 생기고, 서명과는 관계없다.

기관에 따라 직원 PC에 관리자 권한이 없을 수 있다. 감사나 점검이 있을 때 "누가 만든 프로그램인지" 증명하지 못하면 문제가 될 수 있다.

이전 버전은 포터블 exe 하나로 배포했다. USB에 담아 여러 PC에서 쓰는 방식도 필요하다.

여러 PC가 한 호스트에 붙어 쓰므로(0002, 0007), 호스트와 다른 PC의 버전이 다르면 요청 방식이 맞지 않을 수 있다.

## 선택지

**설치 형태**
1. 설치판만
2. 포터블판만
3. 설치판 + 설치 없이 실행만 하는 판 (데이터는 설치판과 같은 곳)
4. **설치판 + 완전 포터블판 (데이터를 exe 옆에)**

**서명**
1. 서명 없이 출시
2. **SignPath Foundation (오픈소스 무료, 심사 있음)**
3. **Certum 오픈소스 개발자 인증서 (연 €49 정도, 실명 공개)**
4. 일반 인증서 (연 15~30만 원)
5. Azure Artifact Signing: 개인은 미국·캐나다만 가능해서 제외

**받는 곳**
1. GitHub 릴리스
2. **GitHub 릴리스 + 한국어 다운로드 안내 페이지**
3. 2 + Microsoft Store

**업데이트**
1. 직접 받아서 교체
2. **새 버전 알림 + 직접 교체**
3. 자동 업데이트 (Tauri updater). 설치판만 지원한다.

## 결정

### 설치판과 완전 포터블판을 같이 낸다

- **설치판 (NSIS `-setup.exe`)**
  - 설치할 때 "모든 사용자용"과 "내 계정용"을 고른다.
  - 모든 사용자용은 관리자 권한이 필요하고, 방화벽 규칙을 같이 등록한다. 방화벽 규칙 등록은 Tauri 기본 기능이 아니라 설치 스크립트에 직접 넣는다.
  - 내 계정용은 관리자 권한이 필요 없고, 첫 실행 때 방화벽 안내를 띄운다.
  - WebView2가 없는 PC에는 설치 프로그램이 같이 깐다.
- **완전 포터블판 (ZIP)**
  - 데이터를 exe 옆 폴더에 둔다. USB에 담아 다른 PC에서 그대로 쓸 수 있다.
  - 방화벽은 첫 실행 때 안내한다.
  - WebView2가 없으면 설치판을 쓰라고 안내한다.
  - 어느 판으로 동작할지 구분하는 방법은 뼈대(5단계)에서 정한다. 예를 들어 exe 옆에 표시 파일을 둘 수 있다.

### 완전 포터블판의 대책

- **호스트가 둘이 되지 않게 한다 (0002 보완).** 폴더를 복사하면 데이터 묶음 ID와 세대 번호까지 같은 사본이 생긴다. 그래서 DB에 마지막으로 연 PC를 기록한다. 다른 PC에서 열리면 "원래 PC에서는 더 이상 쓰지 않는지" 확인한 뒤에 연다.
- **주소가 바뀐다.** USB를 다른 PC에서 호스트로 쓰면 주소가 바뀐다. 다른 PC는 접속이 안 될 때 주소 입력 화면으로 돌아간다(0004의 흐름).
- **USB를 뽑으면 DB가 깨질 수 있다.** 자동 백업은 백업 결정에서 다룬다. 앱을 종료할 때 "안전하게 제거 후 뽑으세요"라고 안내한다.
- **쓰기가 안 되는 곳에 두면** 시작할 때 알아채고 다른 폴더로 옮기라고 안내한다.

### 정식 출시는 서명을 필수로 한다

- 개발 중(5~6단계)에는 서명 없는 시험용 파일을 쓴다.
- 출시(7단계)할 때 SignPath Foundation에 먼저 신청한다. 거절되면 Certum 오픈소스 개발자 인증서를 쓴다.
- 설치판의 설치 파일과 포터블판의 exe를 모두 서명한다.

### 받는 곳은 GitHub 릴리스와 한국어 안내 페이지로 한다

- 파일은 GitHub 릴리스에 올린다. 릴리스 빌드는 태그를 붙일 때만 돈다. 문서만 고친 커밋에는 돌지 않는다.
- 안내 페이지는 GitHub Pages에 둔다. 담는 내용:
  - 어느 판을 받을지
  - SmartScreen이 뜨면 할 일
  - 방화벽 창에서 누를 것
- Microsoft Store는 서명이 생긴 뒤 7단계에서 다시 판단한다.

### 업데이트는 새 버전 알림과 직접 교체로 한다

- 앱이 켜질 때 GitHub에서 새 버전을 확인한다. 새 버전이 있으면 "새 버전 있음 → 받으러 가기"를 보여 준다. 인터넷이 없으면 조용히 넘어간다. 설정에서 끌 수 있다.
- 교체는 직원이 한다. 설치판은 새 설치 파일로 덮어 깔고, 포터블판은 새 파일로 바꾼다. 그래서 접수 중에 호스트가 저절로 바뀌는 일이 없다.

### 버전 번호로 호환을 정한다

버전은 `앞.둘째.셋째` 세 자리로 쓴다(예: `1.2.3`).

| 바뀐 자리 | 언제 올리나 | 호스트와 다른 PC가 다르면 |
|---|---|---|
| 셋째 | 오타, 화면 수정, 작은 버그 | 그대로 접속한다. "새 버전 있음"만 표시한다 |
| 앞 또는 둘째 | 요청 방식, DB 구조, 업무 로직이 바뀔 때. 꼭 받아야 하는 수정일 때 | 접속을 막는다. 어느 PC를 업데이트해야 하는지 안내한다 |

- PC가 호스트보다 새 버전이면 "호스트 PC를 먼저 업데이트하세요"라고 안내한다.
- 꼭 받아야 하는지는 직원이 아니라 유지보수자가 버전 번호로 정한다.
- 버전을 맞춰 보는 구체적인 방법은 뼈대(5단계)에서 정한다.

## 이유

- 감사나 점검에서 방어가 되는 것은 설치 여부보다 서명이다. 서명이 있어야 누가 만들었는지, 받은 뒤 바뀌지 않았는지 증명할 수 있다.
- 설치판은 데이터 위치가 정해지고, 방화벽을 미리 열 수 있으며, 제거가 깔끔하다.
- 포터블판은 설치가 막힌 PC와 USB로 들고 다니는 사용을 받아 준다. 데이터를 exe 옆에 두지 않으면 USB에 담는 의미가 없다.
- 서명은 무료(SignPath)부터 시도하고, 막혀도 저렴한 대안(Certum)이 있다.
- 기관 직원이 GitHub 릴리스 화면에서 맞는 파일을 고르기는 어렵다. 그래서 한국어 안내 페이지를 둔다.
- 자동 업데이트는 접수 중 호스트 변경 위험이 있고, 포터블판을 지원하지 않는다.
- 버전 번호로 호환을 정하면 꼭 필요한 업데이트만 강제할 수 있다.

## 결과

**좋은 점**
- 관리자 권한이 있든 없든, USB로 들고 다니든 쓸 수 있다.
- 꼭 필요한 업데이트만 강제하고, 작은 패치는 직원이 편할 때 받는다.

**감수할 점**
- 두 판을 시험하고 지원해야 한다.
- 포터블판은 USB 분실 시 회원 정보 유출 위험이 더 크다. DB 파일 암호화 여부는 7단계에서 정한다(두 판 모두 해당).
- 서명해도 SmartScreen 경고는 다운로드가 쌓일 때까지 남을 수 있다.
- SignPath를 쓰면 서명의 발행자가 "SignPath Foundation"으로 찍힌다. Certum을 쓰면 유지보수자의 실명이 공개된다.
- 안내 페이지를 하나 관리해야 한다.
- 새 버전 확인은 GitHub에 요청을 보내므로 그때 접속 주소(IP)가 GitHub에 전달된다. 이 기능은 끌 수 있다.
