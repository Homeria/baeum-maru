# 로드맵

배움마루를 만드는 순서와 지금 어디까지 왔는지. 단계 순서는 유지보수자가 정하고, 단계 안의 기능 순서는 진행하며 바뀔 수 있다.

원칙: 바꾸기 비싼 것(도메인 모델, 호스트 구조, 데이터 주인, 모듈 경계, API 모양)을 먼저 정하고, 위험한 가정은 정하기 전에 작게 실험한다.

## 단계

| 단계 | 내용 | 상태 |
|---|---|---|
| 0 | README: 목적, 대상, 하지 않을 것 | 끝 |
| 1 | 도메인: 기준 사례, 기관 유형별 조사, 용어집·업무 규칙·ERD | 끝 |
| 2 | 에이전트 규칙(AGENTS.md) | 끝 |
| 3 | 기술 실험(버리는 코드): 한글 입력, 같은 네트워크의 다른 PC 접속, SQLite 동시 저장, Excel | 끝 |
| 4 | 아키텍처 결정(ADR 0001~0011) | 끝 |
| 5 | 뼈대와 CI: 빈 앱이 Windows 설치판·포터블판으로 빌드되고 실행됨 | 끝 |
| 6 | 기능 | 진행 중 |
| 7 | 보안 강화(ADR 0003 체크리스트), 서명, 출시, 웹사이트 공개 | 아직 |

## 6단계 기능

다 된 것 (괄호는 PR 번호):

- 회원 등록과 검색 (#18)
- 강의실 (#22), 과목 (#24), 학기와 강좌 (#26)
- 직원 로그인 (#30)
- 신청 (#37)
- 추첨 (#39)
- 우선 배정: 자리 보장 (#45)
- 선발 결과: 포기와 대기자 승격 (#47)
- 결과 명단 Excel 내보내기 (#49)
- 자동 백업과 두 번째 위치 (#51)
- 백업으로 되돌리기 (#53)
- DB가 깨졌을 때 로그인 없이 복원 (#55)
- 웹사이트 뼈대와 검사 환경 (Astro, ADR 0019)

남은 후보 (순서 미정):

- 호스트 넘기기 (다른 PC로 데이터 옮기기)
- 추가 신청 (BR-X)
- 확정 단계 (BR-C1·C2)
- 다른 PC 접속과 기기 승인
- 웹사이트 본문 채우기(소개·다운로드 안내)와 첫 블로그 글 (공개 배포는 7단계)

미뤄 둔 것:

- 강의실 시간 겹침 경고, 지난 학기 강좌 복사, 강사 목록
- 학기별 신청 규칙 설정 (BR-A3)
- 우선 배정의 다른 방식(할당, 정원 외, 단계)
- 결과 명단: 우선 색칠 범례, 강사용 출석부, 강좌 하나만 내보내기, 내보내기 기록 화면
- 백업: 클라우드(출시 후), 다른 PC에 복원 알림, 부분 복원

## 7단계 전에 정할 것

- 저장소를 조직 계정으로 옮길지. 서명 신청, 다운로드 페이지 주소, 앱의 새 버전 확인 주소가 저장소 주소에 묶인다.
- 기관용 개인정보 안내의 위치와 분량 (`docs/privacy-notice.md`)
- 정기 RUSTSEC 검사: 의존성 보안 공지는 코드와 상관없이 새로 나온다. 지금은 PR의 cargo-deny 검사에서야 알게 되므로, 정해진 날마다 main을 검사할지 정한다.
