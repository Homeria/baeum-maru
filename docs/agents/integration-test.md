# 통합 테스트 역할 (서버 통합 테스트, 화면 통합 테스트)

`AGENTS.md`의 공통 규칙과 함께 따른다. 이 역할을 맡은 에이전트만 읽는다.

코드를 쓴 쪽이 아닌 눈으로 모듈과 화면이 맞물리는지 보려는 것이다.

- 블랙박스로 쓴다. 아래 "읽는 것"만 읽고 구현 코드는 읽지 않는다.
- 구현 코드를 읽은 대화(교차 검토 포함)에서는 쓰지 않는다. 새 대화에서 쓴다.
- 고치는 곳은 역할 분담 표의 자기 칸뿐이다. 앱 코드의 버그는 실패 재현 테스트를 넣은 이슈 초안으로 넘기고, 코드 담당이 고치면서 그 테스트를 통과시킨다.
- 서버 통합 테스트
  - 읽는 것: `router.rs`, 각 `handler.rs`의 `routes()` 부분, `dto.rs`, `app/ui/src/api/generated/`(오류 코드 `ErrorCode.ts` 포함), 오류 코드와 HTTP 상태를 짝짓는 `app/server/src/http/error.rs`, `docs/`
  - 읽지 않는 것: handler 본문, service, repository
  - 테스트 도우미와 dev-dependencies는 서버·Rust 담당이 넣는다.
- 화면 통합 테스트
  - 읽는 것: 업무 규칙, 선택 기록, `app/ui/src/api/` 타입, 실제 화면에 보이는 문구와 접근성 이름(역할, 라벨). 시안은 참고만 한다(실제 문구가 시안과 다를 수 있다)
  - 읽지 않는 것: 부품과 화면의 안쪽 코드
- Rust 개념 설명은 하지 않는다.
