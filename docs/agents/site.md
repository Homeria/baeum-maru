# 웹·블로그 역할 (site/)

`AGENTS.md`의 공통 규칙과 함께 따른다. 이 역할을 맡은 에이전트만 읽는다.

위치와 배포는 ADR 0019를 따른다.

- 독자는 IT 담당자가 없는 소규모 기관 직원과 도입을 검토하는 사람이다. 개발자가 아니다.
- 문체
  - 설명은 합쇼체로 짧게 쓴다(예: "버튼 한 번으로 이전 상태로 되돌립니다").
  - 질문과 요청은 "~해 주세요", "~할까요?"를 쓴다.
  - 공문서체("~하시기 바랍니다", "~하십시오")는 쓰지 않는다.
  - 기술 용어(DB, 호스트 PC, 릴리스 등)는 `site/` 안의 쉬운 말 대응표를 따른다.
  - 용어집의 말은 그대로 쓴다. 다운로드 페이지와 블로그에서는 용어집 "배포" 절의 풀이를 첫 표기에 붙인다.
- 글감은 선택 기록(`docs/choices/`), ADR, 로드맵과 프로젝트 문서(`README.md`, `docs/domain/`, `docs/privacy-notice.md`)다. 앱 코드를 뒤져 사실을 만들지 않는다. 필요한 사실이 없으면 코드 담당이나 유지보수자에게 묻는다.
- 쓰지 않는 것
  - 로드맵에서 끝나지 않은 기능, 이슈와 선택 기록의 "하지 않는 것", "나중에"인 것을 되는 것처럼 쓰지 않는다.
  - 보안과 개인정보 보호를 부풀리지 않는다. 선택 기록의 근거 표시(원리만 등)를 넘어 단정하지 않는다.
  - 실제 기관 이름과 회원 정보를 쓰지 않는다.
- AI 도움은 사이트 소개에 한 번만 밝힌다: "AI 도구의 도움을 받아 정리하고 제작자가 확인합니다." 글마다 붙이지 않는다.
- 절차
  - 사이트 구조나 디자인을 바꾸거나 새 기획 글(프로젝트 소개, 사용 안내, 개인정보 안내 등)을 쓰는 일은 `AGENTS.md`의 "작업 방식"대로 이슈부터 한다.
  - 근거 이슈나 선택 기록이 이미 있는 내용을 글로 옮기는 일, 문구·오타·링크 수정은 이슈 없이 브랜치와 PR만 쓴다. PR 본문에 근거 이슈 번호를 적는다.
  - git 역할(조회와 스테이징만)과 초안·커밋 메시지 규칙은 `AGENTS.md`와 같다. Rust 개념 설명은 하지 않는다.
- 스크린샷
  - 유지보수자가 `just seed` 더미 데이터로 찍는다. 웹·블로그 담당은 필요한 화면과 상태를 목록으로 요청한다.
  - 필요한 화면만 압축해서 넣는다. 형식과 크기 상한은 `site/README.md`를 따른다.
  - 사진마다 화면 이름과 기준 PR 번호를 기록해 둔다. 평소에는 선택 기록과 PR의 "웹페이지 안내:" 줄을 보고 고친다. 출시 직전과 큰 화면 개편 뒤에 한꺼번에 점검한다.
