# 실험 02: Excel 출력과 가져오기

> 버린 코드다. 결론을 얻기 위한 실험이며 유지보수하지 않는다.

## 확인할 것

1. **결과 명단**: 게시용 명단을 .xlsx로 만들 수 있는가 (이름 가림 BR-R1, 회원번호 BR-R2, 합격/대기 순번)
2. **출석부**: 강사가 종이에 체크하는 양식을 인쇄 설정까지 맞춰 만들 수 있는가
3. **가져오기**: 기관이 쓰던 엑셀 회원 명단을 읽을 때 어떤 함정이 있고 잡아낼 수 있는가

## 방법

- 만들기: `rust_xlsxwriter` 0.102, 읽기: `calamine` 0.38
- 지어낸 이름과 번호로 강좌 2개(정원 초과 1개, 미달 1개)의 결과 명단과 출석부를 만든다.
- 가져오기 시험용 파일에 일부러 함정을 넣고 다시 읽는다.
  - 회원번호, 연락처가 숫자로 저장됨 (앞자리 0 사라짐)
  - 이름 뒤 공백, 이름 없음, 빈 줄
  - 생년월일이 엑셀 날짜 / 글자(`1948.11.02`, `19520715`) / 없는 날짜(`1949-02-30`) / 서식 없는 날짜 번호(`18000`)

## 결과

2026-11-14, Ubuntu에서 실행.

**만들기**
- 한글 시트 이름, 한글 내용 모두 정상으로 저장됐다 (파일 내부 XML로 확인).
- 이름 가림이 글자 수별로 맞게 나왔다: `김○래`, `윤○`(두 글자), `남○○늘`(네 글자)
- 회원번호를 글자로 써서 `00101`처럼 앞자리 0이 남았다.
- 인쇄 설정이 들어갔다: A4, 가로 폭 1쪽 맞춤, 쪽마다 머리글 반복, 출석부는 가로 방향.
- **다른 프로그램에서 확인**: 이 PC의 스프레드시트 프로그램 GridCraft(0.12.1) CLI로 다시 읽어 한글, 가린 이름, `00101` 같은 회원번호가 그대로 보이는 것을 확인했다. PDF로 바꿔 인쇄 모양도 봤다. 표 테두리, 열 너비, 둘째 쪽 머리글 반복이 맞게 나왔고, 출석부는 줄 높이를 20으로 줄여 20명이 한 쪽에 들어가게 했다.
- **LibreOffice Calc(26.2)로 PDF 변환**: 한글까지 나온 인쇄 모양을 확인했다. 결과 명단과 출석부 모두 강좌 하나가 A4 한 쪽에 들어가고, 제목, 머리글 색, 테두리, 가린 이름(`남○○늘`, `윤○`)이 의도대로 나왔다. 대기자 줄이 합격자 줄보다 조금 높게 그려지는 작은 차이가 있었다 (줄 높이를 지정하지 않은 칸을 프로그램이 자동으로 맞춘 것으로 보임).
- **글꼴**: 엑셀 기본 글꼴(Calibri)에는 한글이 없다. 프로그램에 따라 한글이 빈칸이 될 수 있어서 모든 칸에 `맑은 고딕`을 직접 지정했다.

**가져오기**

| 함정 | 결과 |
|---|---|
| 회원번호가 숫자 `124` | 읽음. 앞자리 0이 사라졌을 수 있다고 경고 (원래 값을 알 방법은 없음) |
| 연락처가 숫자 `1012345678` | 앞에 0을 붙여 `010-1234-5678`로 복원하고 경고 |
| 연락처 하이픈 없음 | `010-9876-5432`로 맞춤 |
| 이름 뒤 공백 | 잘라냄 |
| 빈 줄 | 건너뜀 |
| 이름 없음 | 경고 |
| 생년월일 글자 `1948.11.02`, `19520715` | 날짜로 읽음 |
| 없는 날짜 `1949-02-30` | 읽지 못함으로 경고 |
| 서식 없는 날짜 번호 `18000` | `1949-04-12`로 변환하고 확인 필요 경고 |

## 결론

- **Rust로 Excel 만들기와 읽기 모두 충분히 된다.** 인쇄 설정(A4, 쪽 맞춤, 머리글 반복)까지 코드로 정할 수 있다.
- **회원번호와 연락처는 항상 글자로 저장해야 한다.** 숫자로 저장하면 앞자리 0이 사라진다.
- **가져오기는 "그대로 넣기"가 아니라 "미리 보기 → 경고 확인 → 넣기" 화면이 필요하다.** 함정 대부분은 자동으로 고칠 수 있지만, 회원번호 앞자리 0처럼 원래 값을 알 수 없는 경우는 직원이 확인해야 한다.

## 남은 확인

- **Windows Excel에서 한 번 열어 봐야 한다.** GridCraft로 모양은 확인했지만, 실제 기관이 쓰는 Excel(맑은 고딕이 있는 한국어 Windows)에서는 보지 않았다.
- GridCraft의 PDF 변환은 한글을 빈칸으로 그린다. 우리 파일 문제가 아니라 GridCraft가 PDF에 한글이 없는 중국어 글꼴(STSong-Light)을 쓰고 파일에 넣지도 않기 때문이다. 그래서 PDF로는 모양만 보고 내용은 `gridcraft-cli cat`으로 확인했다. 배움마루가 나중에 PDF를 직접 만든다면 한글 글꼴을 파일에 넣어야 한다는 교훈이기도 하다.
- 오래된 `.xls` 파일 읽기는 시험하지 않았다. `calamine`은 지원한다고 하지만 실제 기관 파일 같은 표본이 없다.
- 이름 가림 규칙은 외국인 이름(띄어쓰기 포함, 긴 이름)을 고려하지 않았다.

